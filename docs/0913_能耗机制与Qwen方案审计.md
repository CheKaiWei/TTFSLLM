# 0913：TTFS 方案如何实际降低能耗

> 分析对象：TTFSFormer 原文、当前 Qwen2.5 TTFS MVP，以及原版视觉代码。  
> 原文依据：paper.pdf、[TTFSFormer, ICML 2025](https://proceedings.mlr.press/v267/zhao25n.html)。  
> 代码依据：TTFS_LM/ttfs_lm/modeling_ttfs.py、ttfsformer/spike/ops.py。  
> 文档目的：解释 TTFS 的理论节能路径，检查原论文的能耗推导是否覆盖真实成本，并判断当前 Qwen 代码是否已经获得这些收益。

## 1. 结论先行

TTFS 能耗降低并不是因为把实数写成了一个时间码，也不是因为执行了更多的 encode/decode 就会自动省电。它只有在下面的硬件条件同时满足时才可能降低能耗：

1. 一个神经元在一个推理窗口内最多发放一次；
2. 脉冲到达后只触发权重累加，而不执行激活值乘法；
3. 时间戳直接驱动膜电位或突触状态更新，不恢复完整 dense activation；
4. 非线性时间核由低成本、共享或专用电路实现；
5. 脉冲路由、同步、存储和时钟成本没有抵消算术节省。

因此需要区分三种实现：

| 实现 | 主要计算路径 | 能耗结论 |
| --- | --- | --- |
| 原版 TTFS 理想硬件 | spike arrival -> weighted accumulation -> next spike | 条件成立时可能省能 |
| 原版论文估算 | 统计 AC/MAC 数量并乘固定单价 | 只是理想化估算 |
| 当前 Qwen 代码 | time tensor -> decode -> dense PyTorch op -> encode | 没有已证明的节能 |

当前 Qwen 方案的实际执行更接近：

\[
E_{\mathrm{Qwen,current}}
=
E_{\mathrm{dense\ ANN}}
+E_{\mathrm{encode/decode}}
+E_{\mathrm{range/mask}}
+E_{\mathrm{extra\ kernel}}
+E_{\mathrm{cache\ movement}}.
\]

除非后续实现 event-native backend，否则不能把当前代码的 TTFS 表示直接转换成能耗收益。

## 2. 原版 TTFSFormer 的实际节能机制

### 2.1 TTFS 与 rate coding 的事件数差异

设一层有 \(N\) 个神经元，rate coding 使用 \(T\) 个时间步，平均每个神经元每步发放率为 \(r\)。其脉冲事件数近似为：

\[
N_{\mathrm{rate}}
\approx
NTr.
\]

TTFS 中每个神经元最多发放一次：

\[
N_{\mathrm{TTFS}}
\le N.
\]

如果大部分神经元都发放一次，则：

\[
\frac{N_{\mathrm{TTFS}}}{N_{\mathrm{rate}}}
\approx
\frac{1}{Tr}.
\]

例如 \(T=16,r=0.25\) 时，理想事件数约为 rate coding 的四分之一；若 \(r=1\)，则约为十六分之一。

这是一种 **时间维度上的事件压缩**，不等于空间维度上的稀疏。如果所有神经元都各发一个脉冲，TTFS 仍然可能有接近 \(N\) 个事件。

### 2.2 MAC 变成 AC 的原因

ANN 的一个神经元通常执行：

\[
y_i=\sum_j w_{ij}x_j.
\]

每项需要模拟乘法和累加：

\[
w_{ij}\times x_j+\text{accumulate}.
\]

在事件驱动 SNN 中，输入脉冲是二值事件 \(s_j\in\{0,1\}\)。若 \(s_j=1\)，突触只需把权重加入膜电位：

\[
u_i\leftarrow u_i+w_{ij}.
\]

若 \(s_j=0\)，则没有事件、没有权重访问和累加。于是一次有效脉冲对应一次 AC，而不是一次 MAC。

TTFS 的理想节能来自：

\[
\underbrace{NTr}_{\text{rate event count}}
\times
\underbrace{E_{\mathrm{AC}}}_{\text{per-event cost}}
\quad\longrightarrow\quad
\underbrace{N}_{\text{TTFS event count}}
\times
\underbrace{E_{\mathrm{AC}}}_{\text{per-event cost}}.
\]

这里隐含了一个强条件：权重与时间核的作用必须能通过突触状态或低成本电路实现，不能在每个事件上重新执行一个完整的实值乘法。

### 2.3 原论文的 receiving/emitting 两阶段

TTFSFormer 原文将神经元分为 receiving stage 和 emitting stage。抽象动力学为：

\[
\frac{dV_i}{dt}
=
\frac1{\tau}
\left(
\sum_j w_{ij}\eta_{ij}(t-t_j)+C_i
\right),
\]

在 receiving stage 中累积输入事件；达到 emitting stage 后，再根据输出核 \(\psi\) 产生一个输出脉冲。

其中：

- \(t_j\) 是输入脉冲时间；
- \(\eta_{ij}\) 是输入时间核；
- \(w_{ij}\) 是突触权重；
- \(\psi\) 是输出时间核。

理论上，输入值由到达时间携带，下一层只需处理到达事件，而不需要先生成一个 dense activation。

但两阶段也带来额外成本：

1. receiving/emitting 需要状态寄存器；
2. 需要时间窗口和同步边界；
3. 如果必须等待所有输入事件，延迟不会自动消失；
4. 如果 emitting 与下一层 receiving 不能重叠，端到端 latency 可能增加。

所以 TTFS 的低能耗和低延迟不是同一个命题。少发脉冲主要影响动态能耗；两阶段等待主要影响延迟。

## 3. 原论文的能耗公式如何得到 20%--30%

### 3.1 论文使用的公式

TTFSFormer 在 Section 5.2 中使用：

\[
\frac{E_{\mathrm{SNN}}}{E_{\mathrm{ANN}}}
=
\frac{OP_{\mathrm{SNN}}E_{\mathrm{AC}}}
{OP_{\mathrm{ANN}}E_{\mathrm{MAC}}}.
\]

论文设定：

\[
E_{\mathrm{AC}}=0.9\ \mathrm{pJ},
\qquad
E_{\mathrm{MAC}}=4.6\ \mathrm{pJ}.
\]

因此单次 AC 与 MAC 的理想价格比为：

\[
\frac{E_{\mathrm{AC}}}{E_{\mathrm{MAC}}}
\approx0.196.
\]

如果 SNN 与 ANN 的操作数量相近，就会得到约 20% 的比例。

论文 Table 2 给出的估算为：

| 架构 | \(OP_{\mathrm{SNN}}\) | \(E_{\mathrm{SNN}}\) | \(E_{\mathrm{SNN}}/E_{\mathrm{ANN}}\) |
| --- | ---: | ---: | ---: |
| ViT-S/16 | \(5.42\times10^9\) | 4.9 mJ | 22.3% |
| ViT-B/16 | \(19.2\times10^9\) | 17 mJ | 21.0% |
| ViT-L/16 | \(65.7\times10^9\) | 59 mJ | 20.7% |

这些是基于操作计数和固定单价的估计，不是真实芯片测量。

### 3.2 原论文的操作计数并不意味着操作更少

原文 Appendix C 的 Table 3 给出：

| 层 | SNN 神经元数 | SNN operation count |
| --- | ---: | ---: |
| MatMul \(A\in\mathbb R^{M\times K},B\in\mathbb R^{K\times N}\) | \(MN(K+1)\) | \(MN(3K+2)\) |
| Softmax \(x\in\mathbb R^N\) | \(2(N+1)\) | \(6N\) |
| LayerNorm \(x\in\mathbb R^N\) | \(3N+3\) | \(9N+1\) |
| GELU/SiLU \(A\in\mathbb R^{M\times N}\) | \(MN\) | \(MN\) |

以 MatMul 为例，SNN 构造的操作数渐近为：

\[
MN(3K+2),
\]

而普通 ANN 的乘加数量通常约为：

\[
MNK.
\]

也就是说，TTFS 构造并不是减少了所有操作；它用更多的 AC 或专用神经元操作，换取每次操作更低的理想能耗。

在只看 MatMul 且忽略所有其他成本时，渐近能耗比大约为：

\[
\frac{3K\cdot E_{\mathrm{AC}}}
{K\cdot E_{\mathrm{MAC}}}
\approx
\frac{3\times0.9}{4.6}
\approx0.587.
\]

这已经不是 20%。论文最终得到约 20% 的总比例，依赖于完整 Transformer 的操作组合、首层输入编码假设以及统一 AC 单价，而不能从单个 MatMul 直接推出。

### 3.3 论文估算中隐藏的关键假设

原公式等价于假设：

\[
E_{\mathrm{SNN}}
\approx
OP_{\mathrm{SNN}}\times0.9\ \mathrm{pJ},
\]

并忽略或外部化了：

- 非线性输入/输出核的成本；
- 时间比较、排序和同步；
- membrane state 的读写；
- spike router 和 fan-out；
- 权重存储与访存；
- SRAM/DRAM 访问；
- Softmax 的指数和归一化；
- LayerNorm 的平方、均值、逆平方根；
- KV cache 的读写；
- 编码、解码和时间量化；
- 时钟、等待与发放窗口控制。

因此论文的 20%--30% 结论严格来说是：

> 在广义 TTFS 神经元可以按低成本 AC 实现，且未计入的控制、访存和非线性成本不会主导系统能耗时的理想化估算。

作者在 rebuttal 中也承认非线性神经元可能需要专用硬件，真实成本依赖硬件实现。

## 4. 哪些物理条件下 TTFS 真的会省能

### 4.1 条件 A：时间码必须直接驱动突触

理想路径是：

\[
t_j
\rightarrow
\text{temporal synapse}
\rightarrow
u_i
\rightarrow
t_i^{\mathrm{out}}.
\]

不可接受的路径是：

\[
t_j
\rightarrow
x_j=D(t_j)
\rightarrow
w_{ij}x_j
\rightarrow
E(y_i).
\]

后者只是 ANN 计算的时间编码包装，通常不会省能。

### 4.2 条件 B：事件必须减少实际工作

需要满足：

\[
N_{\mathrm{event}}
\ll
N_{\mathrm{dense\ scalar}}.
\]

如果每个时间码都以 dense float tensor 存储和传输，则：

\[
N_{\mathrm{memory\ access}}
\approx
N_{\mathrm{activation}},
\]

TTFS 的事件优势没有变成系统级优势。

### 4.3 条件 C：非线性核必须可实现

TTFSFormer 的一般构造允许：

\[
\eta=f',
\qquad
\psi(s)
\propto
\frac1{\tau h'(h^{-1}(\cdot))}.
\]

如果这些函数在硬件中需要逐元素执行 log、exp、rsqrt 或复杂 LUT，节能可能被抵消。

一个更可信的硬件设计应限定核族，例如：

\[
\eta_\theta(s)
=
\sum_{r=1}^{R}
a_r\exp(-s/\tau_r)\mathbf1[s\ge0],
\]

并同时报告：

\[
\text{kernel area},\quad
\text{kernel state},\quad
\text{lookup cost},\quad
\text{approximation error}.
\]

### 4.4 条件 D：数据搬运不能成为主导成本

完整系统能耗应该写成：

\[
E_{\mathrm{total}}
=
E_{\mathrm{synaptic}}
+E_{\mathrm{neuron}}
+E_{\mathrm{memory}}
+E_{\mathrm{routing}}
+E_{\mathrm{clock}}
+E_{\mathrm{control}}.
\]

如果：

\[
E_{\mathrm{memory}}
+E_{\mathrm{routing}}
>
E_{\mathrm{MAC}}-E_{\mathrm{AC}},
\]

即使 AC 数量更少，端到端也不会省能。

## 5. 当前 Qwen 代码是否满足这些条件

### 5.1 Linear 仍然是 dense ANN

当前 _linear 执行：

\[
\widetilde y
=
E\left(WD(\widetilde x)+b\right).
\]

代码直接调用 dense nn.Linear，见 modeling_ttfs.py 第 203 行。

没有：

- spike event list；
- binary synaptic accumulation；
- event-triggered weight access；
- membrane potential accumulation；
- early termination。

### 5.2 RMSNorm 仍然是 dense 实值计算

当前 RMSNorm 路径为：

\[
\widetilde x
\rightarrow D(\widetilde x)
\rightarrow x^2
\rightarrow \operatorname{mean}(x^2)
\rightarrow \operatorname{rsqrt}
\rightarrow x\cdot\operatorname{rsqrt}
\rightarrow E(\cdot).
\]

具体实现见 modeling_ttfs.py 第 212 行。

它增加了多个编码边界，但没有把平方、均值或逆平方根变成事件电路。

### 5.3 Attention MatMul 仍然是 dense MatMul

当前 Qwen attention 执行：

\[
\widetilde Q,\widetilde K
\rightarrow
D(\widetilde Q),D(\widetilde K)
\rightarrow
\operatorname{torch.matmul}
\rightarrow
E(\widetilde L).
\]

见 modeling_ttfs.py 第 231 行。

因此 QK 和 AV 都仍然消耗 dense MatMul 的计算与访存成本。

### 5.4 SwiGLU 仍然是 dense gate/up/product/down

当前路径为：

\[
g=W_gh,\qquad
u=W_uh,
\]

\[
z=\operatorname{SiLU}(g)\odot u,
\qquad
y=W_dz.
\]

虽然每个中间角色都有 TTFS range，但实际仍执行 dense Linear、SiLU 和 dense Hadamard。

### 5.5 KV cache 没有事件压缩

当前 cache 保存的是与 K/V 同形状的 dense time tensor：

\[
\widetilde{\mathcal C}_s
=
\left(
\widetilde K_{1:s},
\widetilde V_{1:s},
p_{1:s},
m_{1:s}
\right).
\]

旧 cache 在 attention 中会被解码：

\[
\widetilde K_{1:s}
\rightarrow
D(\widetilde K_{1:s}),
\qquad
\widetilde V_{1:s}
\rightarrow
D(\widetilde V_{1:s}).
\]

TTFSCache 的 append 和 reorder 只是在 dense tensor 上拼接或索引，见 modeling_ttfs.py 第 120 行。

因此它具有 stateful 表示，却没有：

- event-compressed cache；
- sparse timestamp storage；
- event-driven KV read；
- 旧 token 的跳过机制；
- 按到达时间提前终止 attention。

### 5.6 Embedding 和 LM Head 仍然是 dense

当前默认路径：

\[
\text{token id}
\rightarrow
\text{dense embedding}
\rightarrow
\text{TTFS encode}
\]

最后：

\[
\text{decode hidden}
\rightarrow
\text{dense LM head}
\rightarrow
\text{logits}.
\]

只有开启 spike_lm_head 时，logits 才会额外编码；这不会让 LM Head 自动变成事件计算。

### 5.7 当前实现的真实能耗分解

当前代码更接近：

\[
E_{\mathrm{current}}
=
E_{\mathrm{embedding}}
+E_{\mathrm{dense\ RMSNorm}}
+E_{\mathrm{dense\ QK/AV}}
+E_{\mathrm{dense\ SwiGLU}}
+E_{\mathrm{dense\ LM\ head}}
+E_{\mathrm{encode/decode}}
+E_{\mathrm{telemetry}}
+E_{\mathrm{cache\ movement}}.
\]

有限精度下还要增加：

\[
E_{\mathrm{round}}
+E_{\mathrm{clip}}
+E_{\mathrm{intermediate\ quantization}}.
\]

所以当前代码无法从执行路径推出：

\[
E_{\mathrm{current}}<E_{\mathrm{ANN}}.
\]

在 GPU 上，它甚至可能比原 ANN 更慢、更耗电，因为它增加了边界操作和中间张量读写。

## 6. 当前代码与原版 TTFS 专用算术的差异

原版视觉代码至少尝试了专门的 log-domain Hadamard 和 Triton MatMul：

\[
|xy|
=
\exp(\log(|x|+1)+\log(|y|+1))
-|x|-|y|-1.
\]

以及对应的 Triton kernel。见 ttfsformer/spike/ops.py 第 50 行和 ttfsformer/spike/kernel/matmul.py 第 65 行。

但这些实现仍然是 GPU 上的 dense tensor kernel，不是真正的脉冲硬件。

当前 Qwen 方案反而使用：

\[
\operatorname{torch.matmul}(D(\widetilde Q),D(\widetilde K)),
\]

因此从“接近原论文时间算术”的角度看，Qwen MVP 还存在退化，而不是继承了全部原版能力。

## 7. 最值得发展的新能耗 idea：CSD-TTFS

### 7.1 从完整 activation 改成 residual event

当前方案编码完整 hidden：

\[
\widetilde h_l=E_l(h_l).
\]

建议改为只编码 block update：

\[
\Delta_l^{\mathrm{attn}}
=
\operatorname{Attention}(h_l),
\]

\[
\Delta_l^{\mathrm{mlp}}
=
\operatorname{SwiGLU}(h_l),
\]

\[
h'_l=h_l+\Delta_l^{\mathrm{attn}},
\qquad
h_{l+1}=h'_l+\Delta_l^{\mathrm{mlp}}.
\]

只对增量编码：

\[
\widetilde{\Delta_l}
=
E_{\Delta,l}(\Delta_l).
\]

硬件状态保存 \(h_l\)，event 只表示状态更新：

\[
u_l
\leftarrow
u_l+\operatorname{EventAcc}
(\widetilde{\Delta_l}).
\]

这样 residual add 不再需要重新解码两个完整 activation 并生成一个新的 dense time tensor。

### 7.2 静默事件必须具有物理含义

设 update 的绝对值低于阈值 \(\epsilon_l\)：

\[
|\Delta_{l,i}|\le\epsilon_l
\quad\Longrightarrow\quad
\widetilde{\Delta}_{l,i}=\varnothing.
\]

静默意味着：

\[
\Delta u_{l,i}=0,
\]

该神经元无需路由、无需权重访问、无需状态写入。

这与普通量化把数值塞进零附近的一个 bin 不同。普通量化仍然需要 dense tensor 扫描；CSD-TTFS 的目标是让静默值不产生事件。

### 7.3 Stateful KV event memory

第 \(s\) 个 token 的 K/V 只编码一次：

\[
\widetilde K_{l,s}
=
E_{K,l,\phi,e}
\left(R(p_s)W_kh_s\right),
\]

\[
\widetilde V_{l,s}
=
E_{V,l,\phi}(W_vh_s).
\]

cache 保存：

\[
\mathcal C_{l,s}
=
\left(
\widetilde K_{l,1:s},
\widetilde V_{l,1:s},
p_{1:s},
m_{1:s},
\phi,e
\right).
\]

旧 cache 不重新编码；attention 通过 temporal read primitive 访问：

\[
\operatorname{Read}_{\mathrm{temporal}}
(t_q,\widetilde K_{l,1:s},p_{1:s},m_{1:s}).
\]

研究重点是让 read primitive 消费时间事件，而不是先恢复完整 K/V。

### 7.4 Temporal-arrival attention

定义时间域 score：

\[
S_{qk}
=
\operatorname{TemporalScore}
(t_q,t_k,p_q,p_k).
\]

只有：

\[
p_k\le p_q,\qquad m_k=1
\]

的事件进入 accumulator。

如果事件按时间到达，系统可以在输出 margin 已经确定时停止：

\[
L_{v^*}(\tau)
>
\max_{v\ne v^*}U_v(\tau)
\quad\Longrightarrow\quad
\operatorname{argmax}_v z_v=v^*.
\]

这会产生 TTFS 特有的动态能耗：

\[
E_{\mathrm{attention}}
\propto
N_{\mathrm{events\ processed}},
\]

而不是固定处理全部 \(QK^\top\) 元素。

## 8. 一个可审计的真实能耗模型

建议将未来系统能耗写成：

\[
E_{\mathrm{CSD}}
=
N_{\mathrm{event}}E_{\mathrm{AC}}
+N_{\mathrm{temporal}}E_{\mathrm{temp}}
+N_{\mathrm{kernel}}E_{\mathrm{kernel}}
+N_{\mathrm{route}}E_{\mathrm{route}}
+N_{\mathrm{mem}}E_{\mathrm{mem}}
+N_{\mathrm{sync}}E_{\mathrm{sync}}.
\]

其中：

- \(N_{\mathrm{event}}\)：实际产生并处理的脉冲；
- \(N_{\mathrm{temporal}}\)：时间比较、排序和 arrival 操作；
- \(N_{\mathrm{kernel}}\)：非线性 temporal kernel 调用；
- \(N_{\mathrm{route}}\)：脉冲路由和 fan-out；
- \(N_{\mathrm{mem}}\)：权重、状态和 KV cache 访存；
- \(N_{\mathrm{sync}}\)：时间窗口、屏障和控制操作。

ANN 基线应写成：

\[
E_{\mathrm{ANN}}
=
N_{\mathrm{MAC}}E_{\mathrm{MAC}}
+N_{\mathrm{mem}}^{\mathrm{ANN}}E_{\mathrm{mem}}
+N_{\mathrm{norm}}E_{\mathrm{norm}}
+N_{\mathrm{softmax}}E_{\mathrm{softmax}}.
\]

只有实测或可信周期级模型满足：

\[
E_{\mathrm{CSD}}
<
E_{\mathrm{ANN}}
\]

时，才可以宣称端到端节能。

### 8.1 Break-even 条件

若把 event-native 计算简化为：

\[
E_{\mathrm{CSD}}
\approx
N_{\mathrm{event}}E_{\mathrm{AC}}
+E_{\mathrm{overhead}},
\]

ANN 为：

\[
E_{\mathrm{ANN}}
\approx
N_{\mathrm{MAC}}E_{\mathrm{MAC}},
\]

则 TTFS 节能至少需要：

\[
\frac{N_{\mathrm{event}}}{N_{\mathrm{MAC}}}
<
\frac{E_{\mathrm{MAC}}}{E_{\mathrm{AC}}}
\left(
1-\frac{E_{\mathrm{overhead}}}{E_{\mathrm{ANN}}}
\right).
\]

代入论文单价：

\[
\frac{E_{\mathrm{MAC}}}{E_{\mathrm{AC}}}
\approx5.11.
\]

这意味着理论上 overhead 很小时，event 数可以约为 MAC 数的五分之一仍有机会节能；但一旦 memory、kernel 和 routing overhead 很大，允许的 event 数会迅速下降。

- PPL 和 downstream quality 门槛；
- weight storage；
- KV cache storage；
- hardware target。

### 9.3 端到端指标

至少报告：

\[
\{\mathrm{PPL},
\mathrm{NLL},
\mathrm{token\ agreement},
\mathrm{events/token},
\mathrm{bytes/token},
\mathrm{TTFT},
\mathrm{decode\ latency},
\mathrm{energy/token}\}.
\]

不能只报告 AC/MAC 的比例。

### 9.4 当前 MVP 可以立即做的能耗上界

在没有硬件之前，可以先报告严格的“不会节能”证据：

1. 当前 time tensor 元素数与 ANN activation 元素数相同；
2. 当前 QK/AV 仍是 dense MatMul；
3. 当前 RMSNorm/SwiGLU 仍是 dense 实值算子；
4. 当前 cache 没有事件压缩；
5. 当前 embedding 和 LM Head 仍是 dense；
6. 当前没有 event router、膜电位状态或早停。

这些证据足以证明当前代码不能声称端到端节能，但不能据此断言未来 event-native 设计一定不能节能。

## 10. 与 TTFSFormer 的能耗差异

| 方面 | TTFSFormer 原版 | 当前 Qwen MVP | 未来 CSD-TTFS |
| --- | --- | --- | --- |
| 编码对象 | activation | activation | residual update/event |
| 时间是否驱动计算 | 理论上是，代码中主要模拟 | 否，dense decode 后计算 | 是，目标设计 |
| 线性运算 | AC 理想模型/专用构造 | dense Linear | temporal synaptic accumulation |
| MatMul | log-domain TTFS 构造 + Triton | dense torch.matmul | temporal score/event accumulation |
| 非线性 | 广义核 | dense rsqrt/SiLU/Softmax | 受约束 temporal kernels |
| Cache | 无自回归 cache | dense time-coded cache | event/time state cache |
| 早停 | 未证明 | 无 | margin-certified early stop |
| 能耗证据 | MAC/AC 理想估算 | 无 | 需要完整成本模型/硬件 |

相对 TTFSFormer，Qwen 的新增状态问题是有价值的；相对真正的 TTFS 能耗机制，当前 Qwen 还没有跨过 dense fallback 这道门槛。

## 11. 推荐的论文 claim

### 当前可以说

1. TTFS 的理想节能来自单脉冲事件数和 AC 型突触累加；
2. TTFSFormer 的 20%--30% 是基于固定 AC/MAC 单价的估算；
3. 复杂非线性核、访存、路由和同步可能改变该结论；
4. 当前 Qwen 实现是 TTFS functional simulator，不是 event-native backend；
5. 当前代码尚未证明任何端到端能耗下降；
6. Qwen 的关键新问题是 stateful causal temporal computation。

### 当前不能说

1. “time code 本身降低了能耗”；
2. “Continuous TTFS 比 ANN 更省电”；
3. “当前 Qwen P=4096 具备实用节能”；
4. “dense decode-compute-encode 等价于 SNN 硬件执行”；
5. “MAC/AC 单价比例就是端到端能耗比例”；
6. “TTFS cache 自动减少了 KV memory energy”。

## 12. 最终判断

TTFS 的能耗优势可以被压缩成一句严格的话：

> **只有当脉冲时间直接驱动低成本事件计算，并且事件数、非线性核、路由、存储和同步的总成本低于 ANN 时，TTFS 才会实际降低能耗。**

原论文完成了第一步的数学构造和第二步的理想化 AC/MAC 估算，但没有完成真实硬件成本闭环。

当前 Qwen 方案完成的是：

\[
\text{ANN}
\rightarrow
\text{typed temporal representation}
\rightarrow
\text{dense functional simulation}.
\]

它还没有完成：

\[
\text{timestamp}
\rightarrow
\text{event-driven temporal primitive}
\rightarrow
\text{sparse state update}.
\]

因此，最有价值的后续方向是：

\[
\boxed{
\text{Causal-State Differential TTFS}
}
\]

即把 residual update、causal attention 和 KV cache 都改成时间事件驱动的状态更新，并用完整的 energy/token、events/token、bytes/token 和 latency/token 模型验证收益。
